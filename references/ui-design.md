# UI 设计与验证

**按需读取：** 本轮需要设计或明显调整用户界面的信息层级、操作主次、布局密度、组件状态或响应式行为时使用。确定的一处文案、颜色或间距修正，直接检查受影响位置即可；非界面任务不加载，也不因项目含前端就扩大范围。

章节导航：确定任务与风格 → `沿用约束`；安排内容和操作 → `层级与分组`；文字、颜色和素材 → `可读性`；无数据或异常 → `状态与恢复`；实现后 → `实际验证`。按当前问题读取，不要求另做一轮完整设计。

适用边界：讨论和评审保持只读；实现沿用已接受的目标与授权。界面指南不扩大 dev_co 的触发范围，不强制 Figma、独立原型、全站改版或额外审批。需要专项设计技能时遵循主入口的选用规则，复用现有决定与证据。

## 沿用约束

先从请求、当前记录与现有界面确定用户任务、主要操作、内容密度和目标设备。读取已有 `DESIGN.md` 或等效约定，复用品牌、设计变量、组件与平台习惯；没有时从相关页面推断，确有新决定再写入现有记录，不为局部调整新建一套设计文档。

新界面只补当前所需的字体、色彩角色、间距和组件状态。已有流程明确时直接做首个真实实现；只有影响决定的未知才按 [prototyping.md](prototyping.md) 选择代表性试验。品牌营销页、长文阅读、密集数据操作的取舍不同，不能用同一套低密度卡片模板处理。

## 层级与分组

| 当前问题 | 优先尝试 | 保留的边界 |
| --- | --- | --- |
| 内容争抢注意力 | 先用字重、间距和对比度明确主次，必要时弱化竞争元素；灰度检查可帮助判断结构 | 辅助文字仍需可读，不靠巨大标题或小字建立全部层级；无需强制交付灰度稿 |
| 多个操作同样醒目 | 在同一任务区域区分主要、次要与辅助操作，按重要性选择实心、轻背景、描边或文本样式 | 独立任务区可各有主操作；删除等风险仍需明确提示，不能因视觉弱化而隐藏后果 |
| 内容归属模糊 | 让组间距大于组内距；标签靠近对应输入，标题靠近其下内容；不同字号文字混排时检查基线 | 图标和控件按其视觉与点击区域对齐，不对整行所有元素机械使用 baseline |
| 宽度或留白失衡 | 按内容设置宽度，表单与长文避免无意义拉伸；宽松布局可先给足空间再收紧 | 数据表格、日志和高频操作保留必要密度、列宽与分隔，不为留白牺牲比较效率 |
| 卡片、边框或装饰过多 | 先判断间距和背景能否说明分组，只保留有助于归属、状态或操作识别的边界 | 彩色边线和图标容器按用途选用，不统一添加或禁止；清晰的表格和输入边界应保留 |
| 数据标签重复 | 自明的展示数据可省重复前缀，突出对象识别信息 | 表单保留可访问的标签；指标名、单位、时间范围和消歧信息不能删，placeholder 不替代标签 |

## 可读性

- **排版按实际内容调整。** 手机端独立调整大标题比例与布局，不把整个桌面页面等比缩小。控制行长，随字体、字号和行长检查行高；西文的 45–75 字符经验不直接套成汉字数，`ch` 也不代表一个汉字。检查中文多行标题、标点、长名称和中西文混排，不靠缩小正文掩盖溢出。
- **色彩按角色复用。** 优先使用现有的文本、表面、边界、品牌及状态色变量。需要层次时从已有色阶选择，不为凑齐色数创建调色板；品牌强调色与成功、警告、错误等语义色分别管理。浅底深字可降低辅助状态的视觉重量，深色模式按实际背景重新检查。
- **对比度要测量。** 按项目的无障碍要求检查；普通文本以 WCAG AA 4.5:1 为基线，大字（至少 24 CSS px，或粗体至少约 18.7 CSS px）可按 3:1 检查。浅底深字、加深蒙版或降低次要文字明度都不自动证明达标，必要的控件边界和状态识别也要检查。不只用颜色表达状态，配合文字、图标或形状，并保留可访问名称。
- **素材服务于内容。** 图片上的文字检查实际裁切与明暗变化，必要时调整构图、蒙版或文字背景。图标按设计尺寸和笔画比例使用；产品截图应能读到要表达的内容，必要时裁取局部。不要为了填空给所有图标套容器，也不要把简化示意图当作已实现产品的证据。

## 状态与恢复

只覆盖本轮会影响用户任务的状态，用真实长度、密度和关系的数据验证；模拟内容不能伪造服务成功。区分以下原因，不共用一个笼统的“暂无数据”：

| 状态 | 用户需要知道和能做什么 |
| --- | --- |
| 首次无数据 | 说明这里将有什么，提供适用的创建或导入入口；确实无用的空壳控件可以暂时收起，插画可选 |
| 搜索或筛选无结果 | 保留当前条件及其控件，说明无匹配并提供清除或调整入口，不能把恢复路径一起隐藏 |
| 加载中或部分结果 | 说明正在处理或哪些内容尚未完成，按实际行为处理重复操作，避免用空状态误导用户 |
| 失败或无权限 | 说明原因与可执行的下一步；保留适用的输入、选择和位置，区分重试与申请权限；不能假装首次无数据 |
| 操作成功 | 给出可观察的结果；需要持久化的操作应可重新读取，不以 toast 或静态截图代替结果验证 |

例如任务列表首次为空时引导创建；筛选为“已完成”却没有匹配时，保留筛选并允许回到全部。它们可以共用组件，但文案和恢复动作应随原因变化。

## 实际验证

检查深度跟随本轮影响，完成项目要求。局部样式看改动处和相邻元素；布局或流程变化选择代表性界面、目标视口及相关状态，不默认全站审查。

1. **运行并查看。** 查看实际渲染，检查主次、分组、中文换行、溢出和操作可发现性。使用代表性长内容与密度；响应式变化检查相关宽窄视口和缩放。数据表格允许有意的局部横向滚动，页面其他部分仍应可用。已有合适截图可复用；仅截图保存成功不算看过。
2. **走受影响的任务。** 从真实入口操作到可观察结果；按变化检查筛选恢复、输入保留、键盘焦点和目标设备的操作可达性。静态设计只支持视觉结论，行为、持久化和真实集成各需相应证据。
3. **记录具体结论。** 说明检查的页面、视口、状态、版本和剩余缺口，适用时保留前后截图链接。没有运行或看图能力时可做源码检查，但明确未验证实际视觉或交互；不编造评分，也不以截图数量证明质量或用户认可。

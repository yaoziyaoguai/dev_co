# 当前记忆与交接

**按需读取：** 编制执行包、接手、需求漂移、记忆冲突或记录结构需整理时使用。普通继续开发若现行记录已清楚，可直接沿用，不每轮重读本指南。

章节导航：缺少入口 → `先复用，再补缺口`；记录过长/缺项 → `当前记录应该保留什么`；编包/移交 → `执行包与阅读约定`；改向 → `变更想法时`；恢复开发 → `接手步骤`。

适用边界：只维护一份当前记录；历史快照需与当前指令核对，修改时间不决定需求优先级。记忆提供意图和导航，代码与对应版本的验证仍需按本轮影响核实。

## 先复用，再补缺口

先读适用的项目 `AGENTS.md` / `CLAUDE.md` 和它指向的当前记录。入口不明时再用 README 或文档索引定位，不默认读取全部项目文档。已有任务系统/当前记录能承担这些信息时继续用它；不要另建一套平行真相。

没有约定时，按需采用以下结构；后两类只在内容足够复杂时出现：

```text
AGENTS.md / CLAUDE.md   项目命令、约束、当前记录入口；不复制需求正文
README.md              如何使用、启动和验证产品
docs/CURRENT.md         当前目标、有效决定、导航、证据、下一步
docs/decisions/         少量重要且有取舍的长期决定（可选）
docs/archive/           已完成阶段的长记录（可选）
```

入口文件各自服从宿主指令体系。核心过程来自同一技能，项目事实来自同一记录。若已有 `docs/PROJECT.md`、issue 或其他路径，直接用原位置；不要为了模板改名。

使用 `context-save`、`context-restore`、`checkpoint` 或 `handoff` 时，快照记录来源项目、分支、日期和当前记录路径，需求正文尽量引用原记录。恢复前核对当前指令与有效决定；较新的存档时间不代表其中的旧需求重新生效。快照保留历史状态，项目当前记录仍只有一个。

## 当前记录应该保留什么

- **项目依据：** 会影响当前选择的使用者、核心对象、主要任务、阶段和硬约束，引用已有来源；缺少且影响判断时才补，不另建项目画像或复制完整规格。
- **本轮目标与边界：** 要解决的问题、用户可见结果、暂缓内容；需求变化修订当前表述。
- **验收标准：** 观察什么才算完成；实现、效果、真实使用分别有哪些证据要求。
- **当前决定：** 标记有效、候选、已替代；写决定、理由、来源日期/任务和适用范围。旧方向注明由哪条取代，不让两者并列生效。
- **代码导航：** 本轮入口、关键模块、数据流/契约、相关测试和运行方式。指向实际文件/符号，比大段源码复述更有用。
- **推进约定：** 适用的验证层级、汇报节点、质量样本、已明确的成本上限和失败停止条件。个人习惯仅写此项目适用部分。
- **当前阶段与方法：** 本轮主流程、正在使用的专项能力、已有产物位置和未完成的证据。记录会影响恢复的信息，避免接手后重新选型或重复访谈。
- **最近验证：** 命令或手工步骤、结果、覆盖内容、代码版本/工作树、环境、证据位置和未验证项。旧通过记录保留历史身份，不冒充当前通过。
- **下一步：** 未完成项、阻塞需要的具体输入，以及下一条可执行动作。

把当前目标、有效决定、本轮导航、证据缺口和下一步放在记录开头，保持能快速读完；维护时替换已失效的当前表述，已完成阶段的长记录归入历史并留链接，不让当前入口不断累积整段旧交接。长日志和历史推演留在既有位置并链接。不要为 TL;DR 新建第二份当前计划，也不机械搬走仍有效的约束。

使用 `brief` 时，短记录沿用全文；长记录按恢复章节提取，保留正文位置并报告截断、缺项和同名段落歧义。已有标题可在 `brief_sections` 指定，不为了脚本重命名项目文档。它不自动生成语义总结；缺少关键约束就按导航补读。文档移动、归档和更新义务见[仓库增量维护](repository-lifecycle.md)，已有相关约定不重复建立。

启用仓库基线时，当前记录保留有意义的 scope，通用计划用 `verification.repository_scope` 传递。它绑定本轮比较起点，不过滤文件，也不按每次对话变化；同一工作中的小修与补资料继续沿用。一个工作树一份活动基线和当前验证计划，换工作线按[基线来源与换增量](repository-lifecycle.md#基线来源与换增量)完成原验收、checkpoint、归档退出，再接入新增量，不能仅改名字沿用旧通过。

一处权威来源不等于只有一个文件。采用 Spec Kit 等功能流程时，规格、计划和任务在各自原产物维护；当前记录提供功能入口、阶段和证据索引，不复制完整需求或维护另一套勾选状态。其他专项报告保存自己的发现与证据，已有品牌、接口和验收仍从原位置引用。

接手先读当前摘要；只有本轮问题需要追溯，才读取相应历史或详细契约。摘要遗漏关键验收、发生截断或发现矛盾时，补读相关原文。源码仍是实现事实的依据；若项目与文档不符，先查相关差异，不一律以文档覆盖代码或让整个记录作废。

## 执行包与阅读约定

适用于确需多任务执行包或跨 agent 交接的工作；小修不强制编包，不新增文档体系、索引服务或 token 预算平台。详细要求保留在现有权威产物中，组织方式应让实施者按当前任务取用。

- **简短入口：** 给出目标、有效全局约束、非目标、任务顺序/依赖、验收出口和停止条件。资料标明“启动必读 / 当前任务必读 / 具体问题再查”；全局约束必须读，历史材料默认只作索引。
- **任务导航：** 复用稳定任务编号或章节，每项指出用户行为、相关文件/符号/接口、必读章节与前置任务、修改/删除边界、验收与适用检查。跨模块依赖不能省略，未知落点明确待查，不为凑清单编造路径或规定每次最多读几行。
- **单一来源：** 共用约束集中维护，任务引用适用内容；交接 Prompt 给入口、顺序及执行约定，不再次全文复制执行包。现有单文件可以按章节读取，不机械拆成许多任务文档。
- **传递阅读约定：** 交接 Prompt 明确要求实施者先读入口与全局约束，再按当前任务定位代码；复用仍有效的已读内容，缺失、变化或验证需要时补读。长工具输出返回摘要和相关失败片段，完整日志留存并保留真实退出码；必要测试与完成证据不能省略。
- **连续执行与恢复：** 连贯任务/阶段出口记录已完成内容、相关文件、有效验证、未解问题和下一动作。需要压缩时用宿主原生能力保留这些事实和约束；不强制按固定轮数压缩，也不在恢复后重读全部历史。已授权工作继续推进，不为控制上下文增加用户审批。
- **有范围的交叉审计：** 仅在当前任务要求或实际需要时执行。提供本轮共同约束、相关源码/差异和验收依据，历史按需展开；独立生成方案时不预先提供另一方答案，合并稿复审时再提交合并结果。范围变化要补足相关上下文，不能以节省 token 为由取消约定审计或隐去未解决问题。

实现者先跑受影响检查，再完成既定阶段出口；相同输入和环境下仍有效的结果可复用，变化或疑点影响结果时重跑，具体沿[验证范围](verification-and-recovery.md)。这些阅读约定不改变产品要求、代码规则、权限或验收，也不授权自动更换模型、降低推理或增加新工具。

## 变更想法时

“先改成 B，A 暂时不要了”属于明确改向：修订本轮目标，将冲突的 A 标为已替代/暂缓，保留其余约束。“能不能试试 B”通常先作为候选或试验问题，说明是否会占用本轮交付；不要自动实施完整 B。

真正冲突且无法自行判定时，用一个具体决策问题解决；无关工作仍可继续。不能根据文档修改时间就认定哪条意图有效，优先当前明确指令及其适用范围，再看来源和决定状态。

每个有意义的目标/验收变化递增 `goal_revision`（启用脚本时）；不要只在末尾追加一条新想法，留下旧目标仍然有效。纯操作进展不改变目标版本。

沿受影响要求核对契约、技术计划、任务、实现与验证；只更新需要改变的部分，并标记需要重新取得的证据。指纹变化只能发现记录变动，不能自动识别行为影响；语义核对由 agent 基于代码和要求完成。

启用辅助脚本时，默认把未采纳想法单独放在 `## 候选想法`，它不影响现有验证证据；采纳后移入有效目标、决定或验收。自定义进展/候选标题用 `non_intent_sections` 显式替换默认集合，`brief_sections` 只控制摘要，不控制有效意图。不要用文字中的“候选”标签推断脚本会忽略该行，具体指纹边界见[辅助脚本说明](helpers-and-hooks.md)。人工记录仍可沿用项目原格式。

## 接手步骤

1. 读项目入口与当前记录，简短复述本轮目标、有效决定及最重要缺口。需要脚本时运行 `brief`，其输出有长度上限；若被截断，直接读取所需段落。
2. 查当前分支、提交、未提交差异和相关运行环境；沿导航看需要修改的源码、契约与测试。仅在索引缺失、明显过期或影响确实跨模块时扩大范围。
3. 核实最近验证是否仍对应当前输入。已启用脚本可运行 `gate`，它只读证据，不执行测试。不要把接手变成无条件全量回归。
4. 选择下一块可交付结果并继续已授权工作。当前记录不是新的审批点。

交接前刷新当前记录。记录工作树状态与已知有效版本，不擅自提交、推送、重置或清理用户改动。失败试验写明假设、观察和失败原因，保留可复用证据，避免下一个 agent 重试同一路线。

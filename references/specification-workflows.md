# 功能级规格流程与 Spec Kit

**按需读取：** 当前功能需要跨模块的需求追踪、契约约束或长期交接，或项目已有 Spec Kit 产物时使用。普通局部修复、页面微调与独立调研不进入本流程。

## 判断是否值得采用

方法选择由 agent 根据任务和现有项目决定，不要求用户回答“选哪个技能”。已有主流程优先；对新功能，先判断已确认的行为、验收和相互依赖的实施部分，是否需要明确的需求—计划—任务关联。涉及多个角色、接口、数据变化及分段交付时，这种关联可能有价值；文件多或项目大本身不足以说明需要 Spec Kit。

目标仍在探索、真实约束未明时，先补会改变决定的证据或代表性试验。不要用生成规格代替需求判断。常规迭代沿用现有记录；只有规格管理的收益足以覆盖创建和维护产物的成本时，才进入这条路线。用户已明确选用或退出时遵守其选择。

## 核实入口并从当前阶段继续

1. 查看项目是否已有 `.specify/`、当前功能定位及 `spec.md`、`plan.md`、`tasks.md`。以当前安装版本和项目约定为准，读取已有功能来源，避免新建重复功能或从头采访。
2. 分别确认宿主可加载的 `speckit-*` 技能、所需模板/脚本、CLI 及相关工具。磁盘有技能不证明依赖可执行；当前聊天可用也不证明 CLI 子进程已可运行。不要凭另一个宿主的命令或旧文档猜调用方式。
3. 未接入时，先评估本地初始化是否属于当前授权范围，检查现有文件、项目原则和 hooks。允许接入时用当前官方帮助与对应宿主集成，保留已有配置；技能或 CLI 缺失不自动授权安装、外发内容或启用 hooks。需要用户决定时解释实际新增内容与影响，不让用户替 agent 做工具选型。
4. 已有产物满足某阶段时直接复用，核对它们是否仍代表当前需求。只对缺失或失效的部分继续，不重复初始化、不改写已确认范围。

若 Spec Kit 在本宿主不可用，保留需要追踪的验收与依赖，沿现有项目记录继续可完成的部分，并说明没有执行 Spec Kit。不要制造仿制 `speckit-*` 入口或声称存在无需产物的官方“轻量模式”。

## 保留官方流程及真实前置条件

使用当前宿主发现的官方阶段技能，并带上具体功能、范围、已有确认和权威产物位置。根据实际阶段选择 specify、plan、tasks、implement；clarify、checklist、analyze、converge 是否适用由当前缺口和官方前置条件决定。选中后读取对应技能，不把命令名当作可随意拆用的函数。

普通会话内接续阶段技能，与 CLI 的 Full SDD Cycle 工作流不同。后者有自己的人工审核、状态和恢复规则；用户或项目已选择这类流程时，不切换调用方式绕过关卡。阶段技能要求澄清关键行为、处理未完成 checklist 或取得真实授权时，也不能用入口“已自动选择”代替这些条件。

Spec Kit 默认规划有固定产物成本。除核心三件套外，当前版本还可能要求研究、数据模型、验收指南及相关契约；辅助文件未被脚本强制检查，不代表可以声称完整执行了要求生成它们的流程。`analyze`、`converge` 依赖已有规格、计划和任务，不能用于无这些产物的任意项目。

实现期间可按明确子任务进入 UI、契约、测试等专项技能；既有需求、设计和授权直接传入。专项技能结束后把实现与证据关联回当前功能，继续它的阶段。不得因某专项自带规划或提交步骤而另建同范围的总计划、擅自提交或推送。

## 权威产物与完成

- 功能需求以该功能的 `spec.md` 为准，技术决定以 `plan.md` 及其引用为准，任务状态在 `tasks.md` 维护。项目已有不同约定时按实际格式处理，不机械迁移。
- dev_co 的当前记录只保留功能位置、当前阶段、跨功能决定、证据缺口和下一步；不要复制完整规格或维护第二套任务勾选。
- 需求变化时先更新受影响的权威来源，再核对契约、计划、任务与验证的影响。历史决定保留已替代标记；没有变化的部分继续有效。
- 交付前把当前实现重新对照验收，查遗漏、部分实现、矛盾与未经请求的扩展；按适用性使用官方 analyze/converge，保留其真实发现和剩余任务。
- 任务勾选、模型一致性报告和 CLI 步骤成功都不证明实际行为正确。完成仍需当前版本的项目检查及本轮约定的真实证据；达到约定结果或预算边界后停止，新的改进另记候选。

来源与版本：此接入原则核对过官方 Spec Kit 1.2.4 的阶段技能与 Full SDD Cycle 1.0.1；具体调用和模板仍应按项目已安装版本确认。参考 [Agentic SDD](https://github.com/github/spec-kit/blob/v1.2.4/docs/reference/agentic-sdd.md) 与 [既有项目接入](https://github.com/github/spec-kit/blob/v1.2.4/docs/guides/existing-projects.md)。本指南不保证跨宿主端到端执行。
